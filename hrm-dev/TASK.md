## 使用说明

1. **执行顺序**：按阶段 A → B/C（可并行）→ D → E 推进；阶段内按依赖列（前置任务全部「已完成」才可开始）。推荐路径：`A01/A02 → B01（与 C01 并行）→ B02~B08 → A03/A04 → B09~B16 → C02~C10 → A05/B17/C11 → D01~D05 → E01~E06`。
2. **本机无 JDK/MySQL/Redis**：B/C 阶段任务验收 = 代码完成 + 结构自检（对照验收标准静态审查）；编译、启动、运行验证统一收敛到 B17、C11 与 D/E 阶段。
3. **状态标记**：任务完成后将「状态」列改为【已完成】，并自检无 BUG 后再开始下一个任务；跨阶段并行仅限无依赖任务。
4. **分支纪律**：按模块建 `feature/*` 分支开发，合入 `dev` 联调；Commit 信息遵守「类型: 中文描述」规范。
5. **文档同步**：涉及表结构/接口/需求的变更，必须同步更新 `docs/` 对应文档后方可标记完成。

优先级：P0 = 上线必须；P1 = 一期内交付；P2 = 增强项（允许上线后补齐，但交付物必须存在）。
