## 1. 目标与边界

### 1.1 本期目标

把驿站包裹数据**自动采集并落进自己的库**，让站长/管理员在系统内查到本站包裹。

拆成三句话：

1. **取得出来** —— 能从 `mdkd.pinduoduo.com` 稳定取到运单数据（P1）
2. **存得下来** —— 能按幂等键落库、可增量、可断点续采（P2/P3/P4）
3. **看得见** —— 站长在系统内看到本驿站数据（P5）

**用户明确的口径（2026-09-19）**：先打通「数据能提取出来」，**分析与深度设计往后放**。据此，P1 的交付物是**落地的数据文件**，不是库表；数据层设计（分区/归档）排在 P3 之后。

### 1.2 明确不做（非目标）

| 不做 | 原因 |
| ---- | ---- |
| 不逆向 `anti-content` 签名、不自行构造 HTTP 请求 | ADR-C04 + 合规红线 C3（硬排除） |
| 不做反检测伪装（UA 轮换 / 代理池 / 指纹对抗） | 红线 C3 |
| ~~不代管站长账号密码、不自动登录~~ → **2026-09-19 决议修订**：站长**书面授权**且满足生效硬前置时，允许以 DPAPI 加密托管平台凭据并自动登录（硬前置见 ADR §20.2.9；不许做的事见 ADR §20.9） | ADR-C02/C05、§10.2 已按 ADR §20 修订 |
| 不回写平台（不用「运单导入」） | ADR 约束 B7，采集端只读 |
| 不做包裹数据的 Excel/CSV 导出（面向用户） | ADR 10.3，收件人数据不对外导出 |
| 本期不接第二个驿站平台 | ADR-C16，仅保留扩展接口 |
| 不做数据可视化/报表分析 | 用户口径：后期再分析 |

## 3. 总体路线

```text
P0 前提闭环 ──┬──> P1 取数 PoC ──> P2 采集端最小可用 ──> P3 服务端与落库 ──> P4 增量与缺口 ──> P5 可见性与上线
              │        ▲                    ▲                    ▲
              │        │                    │                    │
              └────────┴────────────────────┴────────────────────┘
                    （V11/数据库环境可在 P2 期间并行准备）

P1 是分水岭：拿到数据文件 = 项目成立；拿不到 = 回头重估路线
```

**顺序原则**：

1. **P1 先于一切**（用户口径：先能提数）—— P1 之前只做 P0 中**真正挡路**的项（Q1→V2、Q4）
2. **P3 的 DDL 不能早于 P1** —— 没有真实字段样本，表结构就是猜
3. **P4 不能早于 P2** —— 没有稳定的采集端，谈不上增量与缺口

### P1 取数 PoC ⭐ **本阶段是用户当前最关心的**

**目标**：**把数据真的取下来，落到文件**。不建库、不做服务端、不做界面。

**退出准则**：单站全量取数成功落地为文件；连续 3 天增量取数成功；全程未触发熔断；**ADR 18.3 三条 CDP 补丁全部落地并验证**。

> **三条 CDP 补丁（ADR 18.3）必须在 P1 阶段落地验证，不得推迟到 P2** —— 它们属于"不打就表现为隐性失败"的坑，越晚发现代价越高。

**P1 期间必须遵守**（红线落地，不因是 PoC 而放松）：

- 并发 = 1、请求间隔下限（ADR-C14）、命中熔断即终止并出报告
- 日志脱敏：不打印运单号/收件人/手机号全量
- 落地文件不入 Git，放受控目录
- **不做反检测伪装**（不轮换 UA、不用代理、不注入对抗脚本）

**P1 的技术选型提示**（借鉴开源实现，只借思路不搬代码）：

- 队列与断点：借鉴 Crawlee `RequestQueue` 的**持久化游标**思路（本项目固定并发 1，不采用其自动伸缩与代理轮换）
- 常驻形态：借鉴 Vercel Labs agent-browser 的「控制端 + 常驻 daemon」分离（P2 落地，P1 可先用单进程）
- 浏览器连接：借鉴 BrowserForce 的「CDP 连接已登录浏览器、不托管登录态」思路

### P2 采集端最小可用

**目标**：把 PoC 固化成可常驻、可远端控制的采集端。

**退出准则**：采集端连续运行 7×24 无人工干预；服务端可下发任务并收到回推；崩溃自愈 < 60s。

| P2-02 | L7 平台适配器（多多）：入口路由 / 触发计划 / 响应匹配 / 分页规则 / 字段映射 | 后端工程师 | P1-06 |

## 12. 质量属性保障措施

> 本章把 ADR 第 4 章的 NFR「设计目标」落到「开发期可自动校验的手段 + 可检查的验证动作」。技术方案本体见 ADR 第 7 章与 ADR-C08，阶段任务与退出准则见 §4 / §7，角色见 §5，本章不复述。

### 12.1 可维护性

| 目标 | 开发期保障手段（尽量做成自动校验） | 验证方式 |
| ---- | ---- | ---- |
| **分层边界不可越过**：L4–L6 不得依赖具体平台实现（不得导入 L7 适配器、不得出现平台业务字段名）；L2 守护进程层保持「薄」，只做进程/心跳/装配，不解析业务字段 | 用 `import-linter` 声明分层契约（L7 → L4/L5/L6 单向；L4–L6 **禁止**反向导入 L7）；L2 目录额外挂一条业务字段名黑名单扫描（AST 扫描，命中即失败）。具体契约写法以 import-linter 官方文档为准 | CI 跑 `lint-imports`（或本地 pre-commit），契约失败即阻断合并；MR 评审逐条对照 ADR-C08 |
| **配置与代码分界纪律**：接口路径 / 入参模板 / 分页规则 / 字段映射 / 限速参数 = 服务端下发配置；触发与解析引擎 = 代码（ADR-C15） | `config/`（配置）与 `core/`（引擎）目录物理分离；把平台请求字段名（`query_waybill`、`inCabinetTime` 等）写入黑名单文件，L1–L6 目录 grep 命中即失败；下发配置必须通过 JSON Schema 校验才允许热加载 | CI grep 黑名单校验；配置 schema 校验失败即拒绝加载（见 12.2 兼容策略） |
| **日志脱敏规范执行**：日志与异常堆栈不打印运单号 / 收件人 / 手机号全量（红线 C5，ADR 9.4） | 复用一期同一份脱敏工具（K14），日志格式化器在落盘前统一过脱敏函数 | 单元测试构造含 11 位手机号 / 长运单号的对象，断言输出无连续数字串；MR 评审清单含该项 |
| **`TODO(扩展):` 标注纪律**：预留能力统一可检索 | 代码内一律 `TODO(扩展): 说明`；提交/PR 描述附本次新增的 TODO 清单 | CI `grep -r "TODO(扩展)"` 统计并与上期对比，无说明的 TODO 判失败 |
| **依赖清单白名单**：依赖清单**明令禁止** stealth / proxy / 反检测类库（红线 C3、K12） | `requirements.txt` + 锁定文件固定版本；CI 脚本对依赖名做关键词黑名单匹配（`stealth` / `undetected` / `fingerprint` / `proxy` / `camoufox` / `nodriver` 等，**最终词表以 ADR-C04 排除项为准**）；新增依赖须评审 | CI 黑名单校验失败即阻断；每阶段退出人工复核一次依赖清单，对照 ADR 第 6 章借/不借清单 |

### 12.2 可扩展性

| 目标 | 机制 / 落地步骤 | 验收标准 |
| ---- | ---- | ---- |
| **新增平台适配器有标准路径**（ADR-C16，注意新增平台**必须发版**，K17） | ① 在 L7 新建适配器，实现五件套接口（入口路由 / 触发计划 / 响应匹配 / 分页元信息 / 字段映射）；② 服务端新增该平台配置（含 `min_collector_version`）；③ **重新评估该平台合规性**（C16：不得沿用本 ADR 结论）；④ 单站灰度验证窗口增量；⑤ 发版 | 核心层 diff 为空（L1–L6 零改动）；依赖检查通过；单站 1 天窗口增量成功且无熔断；合规评估记录归档 |
| **配置版本化、不静默降级** | 下发配置带 `config_version`（单调递增）与 `min_collector_version`（**拟字段名，待 P3-02 定稿**）。采集端启动与热加载时校验：① `config_version` 低于本地已加载版本 → 拒绝加载并告警（防回滚覆盖）；② `min_collector_version` **高于**采集端当前版本 → **拒绝启动 / 拒绝加载 + 告警**，**不得静默降级** | 构造「低版本配置」「采集端版本低于下限」两组用例，断言均拒绝并出告警；加载成功的版本随心跳上报（见 13.1） |
| **数据规模扩展路径与触发条件**（ADR-C11 / C13） | 路径：`station_id` HASH 分区（在线主表）→ 冷热分离 + `parcel_archive` 时间 RANGE 归档 → 多机拆分。触发条件见下表 | 触发即执行并留痕；未触发不提前动表 |

| 扩展动作 | 触发条件 | 动作 | 依据 |
| ---- | ---- | ---- | ---- |
| 分区 | 建表即启用（10^7 行目标） | 按 ADR-C11 建 `station_id` HASH 分区 | ADR-C11、NFR 第 4 章 |
| 归档 | 热区单站行数 > 200 万 或 全库在线行数 > 3000 万（**拟阈值，须 V11 后校准**） | 启动按月下沉 `parcel_archive`，归档前做连续性校验 | ADR-C13 |
| 多机拆分 | 单机日预算占用 ≥ 20h（V9 核算触顶）或 K8 资源告警 | 按站点分机，队列与游标随机器迁移 | K8、V9、ADR-C01 |

### 12.3 性能稳定性

| 目标 | 开发期保障手段 | 验证方式 |
| ---- | ---- | ---- |
| **单机日预算（≤20h）核算与看板**（ADR 第 4 章硬约束） | 核算式：`Σ(各站当日采集时长 + 补采时长) ≤ 20h`；站点数上限 = 20h ÷ 单站耗时（ADR-C14 / V9）。看板展示「时长占用率 = 实际采集时长 / 20h」 | > 80% 预警、≥ 100% 告警并**暂停新增站点**；数据源为 `sync_log ∪ 心跳`；上限值待 P1-04 回填 |
| **限速间隔下限的参数治理（依赖 V8）** | 间隔下限是本方案**唯一容量杠杆**（ADR-C14）。任何变更须：① 架构师复核 + 主智能体审批；② **回填 ADR-C14 与 ADR 第 4 章 NFR**；③ 重算 V9 容量；④ 依据与审批留痕 | ADR-C14 的「依据」字段不得为空；V8 未闭环前**不得据 3s 做任何容量承诺** |
| **首灌耗时基线建立与偏离告警** | 基线 = P1-04 实测单站端到端耗时（回填 ADR-C14 与 V9） | 后续任一站首灌 / 全量轮扫耗时偏离基线 ±30%（**拟阈值**）即告警并排查（限速升级 / 结构变化 / 风控降速） |
| **本地 SQLite 游标与日志的磁盘水位** | 游标与滚动日志同盘（ADR-C10）；磁盘可用率 < 20% 告警 | < 10% **停止领取新任务**（保护游标写入）并告警；20% / 10% 为**拟值**，P2-01 按实际磁盘容量校准 |
| **长跑稳定性观测项** | 观测 daemon uptime、崩溃自愈次数与耗时（目标 < 60s）、Chrome 进程数 / 句柄数 / 内存、心跳缺失次数、SQLite 文件增长 | P5-03 演练 + 长跑记录；异常项统一并入 13.1 指标 |

> **本章与已有章节的关系**：本章只回答「质量属性如何被持续保证、怎么自动查」；目标值来源见 ADR 第 4 章，阶段退出准则见 §7，角色见 §5，技术方案见 ADR-C08/C11/C13/C15/C16。不复述阶段任务与方案细节。

## 13. 迭代优化机制

### 13.1 度量指标体系

> 全部指标均落在既有术语上（`sync_task` / `sync_batch` / `sync_gap` / 熔断报告 / 心跳），不新造概念。

| # | 指标 | 含义 | 采集方式 | 告警阈值 | 责任角色 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| 1 | 窗口闭合率 | 闭合站点数 / 应采站点数 | `sync_task` + `sync_gap` 日聚合 | **非 100% 即处理**（硬指标，ADR-C18） | 运维工程师 + 主智能体 |
| 2 | 缺口数 | `sync_gap` 中未 `closed` 的条目数 | `sync_gap` | ≥ 1 即告警 | 后端工程师 |
| 3 | 熔断触发次数 | 单站 7 日内 `INTERRUPTED` 次数 | `sync_task` + 熔断报告 | 单站 7 日 ≥ 2 次告警；≥ 3 次降频或暂停该站 | 运维工程师 |
| 4 | 登录态失效次数 | `BLOCKED` 次数 | `sync_task` | 任一站点失效即告警（并触发 V10 恢复通道） | 运维工程师 + 主智能体 |
| 5 | 单页取数耗时 P95 | 页级请求耗时分位值 | `sync_log`（页级摘要） | > 基线 2 倍 或 > 5s 告警 | 后端工程师 |
| 6 | 批次成功率 | `SUCCESS` / (`SUCCESS` + `FAILED`) | `sync_batch` | 单站立连续 2 批失败告警 | 后端工程师 |
| 7 | 落库幂等冲突数 | 6003（批次重复/已提交）计数 | 回推接口错误码统计 | 非预期重复 > 0 即排查 | 后端工程师 |
| 8 | 配置版本分布 | 各在线采集端加载的 `config_version` 分布 | 心跳上报 | 存在低于当前基线版本 → 按 12.2 拒绝加载/升级 | 运维工程师 |
| 9 | 采集端在线率 | 心跳正常时长 / 应在线时长 | `collector_node` + 心跳 | 连续 3 次心跳缺失判离线（ADR-C19） | 运维工程师 |
| 10 | 单机日时长占用率 | 当日采集时长 / 20h | `sync_log` + 心跳 | > 80% 预警；≥ 100% 告警并停止新增站点 | 架构师 |
| 11 | 首灌耗时偏离率 | 实测耗时相对 P1-04 基线的偏离 | `sync_log` | ±30%（拟）即告警 | 架构师 |
| 12 | 响应结构突变告警数 | 结构突变类熔断次数（K4） | 熔断报告 | ≥ 1 即熔断并告警 | 后端工程师 |

### 13.2 发布节奏与版本规范

| 项 | 约定 |
| ---- | ---- |
| 版本独立 | 采集端与服务端**各自独立**版本号，互不绑定 |
| 采集端版本号 | `MAJOR.MINOR.PATCH`：MAJOR = 分层接口 / 适配器契约不兼容；MINOR = 新增适配器或能力（向后兼容）；PATCH = 缺陷修复。标签形如 `collector-v1.2.0`（**拟，待 P2 定稿**） |
| 服务端版本号 | 沿用一期现有版本规范（见 deploy.md） |
| 版本锁定（K7） | 浏览器禁用自动更新；采集端依赖锁定（lock 文件）；服务端配置锁 `config_version` |
| 升级通道 | 版本化产物（含校验和）+ 服务端下发版本清单 → 采集端自检 → 人工确认 → 升级（ADR-C19）。**生产只拉 Git 代码，禁止在服务器手改源码**（项目规则 §4、T9） |
| 兼容矩阵 | 三维：采集端版本 × 配置 `min_collector_version` × 平台适配器版本；任一不满足即拒绝加载（见 12.2） |

### 13.3 灰度放量门槛

| 放量档 | 对象 | 放量判据（**全部满足**才可放量） |
| ---- | ---- | ---- |
| 1 站 | 首个站点 | P5-04 首灌完成 + 连续 14 天增量无缺口（§7 P4）+ 无未闭环熔断 / 登录失效 |
| 少量站 | 2–4 站 | 单站模态稳定 ≥ 14 天；日时长占用率 < 80%；V10 恢复流程已实测走通一次；Q2 账号关联风险已书面知情 |
| 全量 | 受容量上限约束的全部站点 | V9 容量核算通过（Σ 日耗时 ≤ 20h）；13.1 全部指标无红灯；灰度期间无 K1 缺口 |

> 每档至少观察 14 天（与 §7 P4 退出准则同口径）。站点数上限由 P0-09 / V9 结论决定。

### 13.4 反馈回路

闭环：`指标 / 告警 → 复盘定性 → 改配置或改代码 → 执行 → 验证 → 回填文档`。

**分界（ADR-C15 / C16 + K17）**：

- **改配置不发版**：接口路径 / 入参模板 / 分页规则 / 字段映射 / 限速参数（**仅限已有平台**）。
- **改适配器要发版**：新增平台、L7 触发与解析逻辑变更、核心层变更。

| 事件 | 定性 | 处置 | 回填 |
| ---- | ---- | ---- | ---- |
| 字段名 / 路径 / 参数类问题 | 改配置 | 服务端改配置 → 灰度单站 → 全量 | ADR-C15 适用范围、update-log |
| 适配器 / 解析逻辑问题 | 改代码 | 改 L7（或核心层）→ 发版 → 灰度 | ADR-C16、本规划 §13.7、update-log |
| 新增平台 | 改代码 | 走 12.2 五步 | **新增 ADR 条目** |

### 13.5 ADR 变更流程

**任一命中即必须新增或修订 ADR**：

1. 触碰合规红线 C1–C5；
2. 变更 ADR-C01 / C02（部署形态 / 账号模式）、C08（分层边界）、C11 / C12（分区 / 唯一键）、C14（间隔下限）、C15 / C16（配置 / 适配器边界）、C20（接口契约）；
3. 新增平台；
4. V2 / V3 / V8 / V9 / V10 / V11 结论落地需回填。

**流程与批准**：架构师提议（新增 / 修订条目）→ 主智能体 `code-review` 四维审查 → **红线与业务口径类由用户拍板，技术类由主智能体批准、架构师执行** → 回填 ADR → 同步复核本规划与 db.md / api.md / deploy.md（按 §14.3 仲裁）→ update-log 留痕。

### 13.6 技术债登记与偿还

| 项 | 约定 |
| ---- | ---- |
| 登记位置 | `hrm-dev/docs/update-log.md` 的「技术债」小节（拟新增）；代码内以 `TODO(扩展):` 就地登记并引用债务编号 |
| 分级 | **P0 阻塞**：影响红线合规或导致静默失败 → 当阶段内必须清偿；**P1 计划**：影响可维护性 / 稳定性但有绕行 → 下一阶段退出前清偿；**P2 可延后**：体验 / 优化类 → 排后续迭代 |
| 偿还窗口 | 每阶段退出评审（15.2 Gate）逐条核对；**P0 未清零不得通过 Gate** |

### 13.7 回归策略

| 变更类型 | 回归范围 | 通过判据 |
| ---- | ---- | ---- |
| 改配置（已有平台参数） | 单站 1 页取数 + 字段映射断言 + 响应结构校验（**不发版**） | 字段无缺失、结构校验通过；灰度单站 1 天窗口无缺口 |
| 改代码（L7 适配器 / 核心层） | 分层契约检查（12.1）+ 单测 + 单站全量窗口 + 断点续采 +（涉熔断逻辑时）熔断演练 | 全部通过且核心层边界未破 |
| **页面版本横幅变化** | 立即**暂停**受影响站点 → 按 ADR 17.1 方法静态分析 bundle → 重跑字段映射 → 单站回归 → 放量 | 映射与实测一致、结构校验通过 |

> 版本横幅实测形如 `v20260913.16.22.43#20250325#info`（ADR-C19 / K7）。横幅变化即触发上表第三行动作，**不得先观察后处理**。

> **本章与已有章节的关系**：本章只补充「如何度量、如何迭代、如何回退」的机制；阶段划分与退出准则见 §4 / §7，风险与待验证项编号沿用 ADR 第 11 / 12 章，配置文件与适配器的边界见 ADR-C15 / C16。不复述技术方案。

### 14.5 禁止项

- 真实业务数据：运单号 / 收件人 / 手机号 / 地址 / 机构码实值。

示例一律用占位符；违反按项目规则 §6 安全红线处理。

## 15. 团队协作流程

### 15.1 标准协作节奏

每阶段固定动作序列：**对齐 → 分派 → 执行 → Review → 验收 → 文档回填 → 检查点写入**。

| 动作 | 内容 | 责任人 |
| ---- | ---- | ---- |
| 对齐 | 读 SESSION-STATE + 本规划，输出 `[对齐]` 行（项目规则 §0） | 主智能体 |
| 分派 | 按 §5 矩阵分派并加载对应强制技能（项目规则 §9） | 主智能体 |
| 执行 | 子智能体按各自 SKILL.md 完整流程产出 | 子智能体 |
| Review | 主智能体 `code-review` 四维审查 | 主智能体 |
| 验收 | 对照阶段退出准则（§7）判定 | 主智能体 |
| 文档回填 | 按 14.4 清单回填 | 主智能体 |
| 检查点 | 写 SESSION-STATE.md | 主智能体 |

### 15.2 评审门（Gate）

| 项 | 内容 |
| ---- | ---- |
| 参与者 | 主智能体（主持）、该阶段产出子智能体、架构师（涉 ADR 变更时） |
| 通过条件 | ① 阶段退出准则（§7）全部满足；② 13.6 中 **P0 技术债清零**；③ 14.4 文档回填完成；④ 未违反红线 C1–C5 |
| 不通过处置 | 列未达标项 → 退回重做 → 阻塞项登记为技术债（13.6）→ **不允许「带病进入下一阶段」** |
| 例外 | 需用户拍板的（红线 / 成本 / 口径）在拍板前 Gate 挂起 |

### 15.3 权责边界

- **主智能体 = 最高权限**：需求拆解、编排调度、安全审查、Review；**独占 MCP 调用**（浏览器控制、宝塔、SSH）。
- **子智能体**：只做本角色任务，产出经主智能体 Review 后方可落地；**不得直接调用 MCP**。
- **禁止主对话越俎代庖直接产出实现**（项目规则 §8）；遇对应任务必须走子智能体分派。
- 服务器 / 宝塔操作走「安全评估 → 应急预案 → 确认执行」三步（全局规则 §6）。

### 15.4 长线任务的上下文管理

- **检查点写入 SESSION-STATE.md 的时机**：每阶段启动时、每阶段退出时、每个 Gate 通过后、重大实测结论产生时（如 P1-04 / V2 / V10 结论）。
- **上下文超 70%**：先把当前分工、文件路径清单、待办与已完成摘要外存到 SESSION-STATE.md，再触发压缩；压缩保留「目标 + 约束 + 待办 + 改动记录」（全局规则 §7）。
- **子智能体隔离**：分派时只传「目标 + 文件路径 + 约束」，不传完整对话；回收时只要「摘要 + 改动清单」，实现细节留在文件里。

### 15.5 多角色并行冲突处理

- 同一文件 / 同一文档同一时间**只能有一个写者**；跨角色需改同一文件时由主智能体**串行化**（后者在前者合并后再开始）。
- **文档写权归属**：ADR 归架构师、本规划归主智能体、db.md 归数据库工程师、api.md 归后端工程师、deploy.md 与装机 checklist 归运维工程师；他人只提修订建议，由责任人落笔。
- **代码目录按 L1–L7 边界划片**，同一层同一模块不并行分派两人。

### 15.6 应急协作

| 事件 | 上报路径 | 处置责任 | 状态 |
| ---- | ---- | ---- | ---- |
| 熔断（验证码 / 403 / 429 / 跳登录 / 结构突变） | 采集端 → 熔断报告 → 服务端告警 → 主智能体 | 运维工程师暂停该站 → 架构师定性 → 按 13.4 改配置或改代码；**熔断后禁止自动绕过** | 可闭环 |
| 登录态失效 | 采集端 → `BLOCKED` 告警 → 主智能体 | 需人工在该机上完成登录（V10） | **阻塞**：V10 未闭环，指向 **P0-06**；P0-06 完成前不具备长期可运行性（K16） |
| 断网 | 采集端心跳缺失 → 离线告警（ADR-C19） | 运维工程师恢复网络 → 断点续采（本地游标，ADR-C10） | 可闭环 |

> **如实标注**：登录态失效场景中「集中部署下由谁上机完成登录」为**未闭环项**（V10 / K16），本流程不掩盖该阻塞，恢复责任在 P0-06 结论落地前无法指派到具体角色。

### 15.7 交接机制

人员 / 会话更替时按以下清单交接，并在 SESSION-STATE.md 留痕：

1. 读 SESSION-STATE.md（进度 + 环境约束 + 遗留）；
2. 读本规划（阶段 / 责任 / 退出准则）；
3. 读 ADR（决策 + 待验证项）；
4. 确认当前分支与最近提交（项目规则 §1）；
5. 确认 13.6 技术债台账；
6. 确认未闭环阻塞项（当前为 **V10**）。
