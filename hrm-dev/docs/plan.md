## 2. 一期（详细）

### 2.1 目标

从零搭建可部署、可验收的管理系统底座：后端（`hrm-server`）+ PC 管理端（`hrm-admin`），功能范围以 [requirement.md](requirement.md) 为准，P0 功能全部上线，P1 功能上线后一周内闭环。

### 2.2 里程碑

里程碑与 [../TASK.md](../TASK.md) 任务编号对应，退出准则即该组任务的验收标准。

| 里程碑 | 内容 | 包含任务 | 退出准则 |
| ---- | ---- | ---- | ---- |
| M0 设计冻结 | 设计文档评审通过 | - | 4 份设计文档定稿（本文档集） |
| M1 基础框架与登录闭环 | 工程骨架、认证链路、第一条端到端流程 | A01-A04、B01-B09、C01-C04 | 代码结构完整；登录/退出/me/改密接口与前端登录页按 api.md 实现完毕 |
| M2 组织架构管理 | 部门与驿站管理 | B10、B11、C08、C09 | 部门树/驿站 CRUD 与全部业务校验（3002/3003/3004/4002/4003/4004）实现 |
| M3 员工管理 | 员工全生命周期 | B12、B13、C06 | 分页筛选、增删改、启停、重置密码、自我/最后管理员保护全部实现 |
| M4 导入导出与看板 | 批量能力与数据概览 | B14-B16、C05、C07、C10 | 模板/导入/导出/看板按 api.md 第 4.2/4.3/5/6 章实现 |
| M5 部署与验收 | 上线 | B17、C11、A05、D01-D05、E01-E06 | 服务器从零部署成功；requirement.md 第 9 章验收门槛全项通过 |

### 2.3 执行方式

- 任务由不同执行者（智能体/开发）按 [../TASK.md](../TASK.md) 顺序领取，A/B 阶段与 C01-C03 可并行；
- 分支策略遵守仓库 CONTRIBUTING：按模块建 `feature/*` 分支，经 `dev` 联调后合入 `main` 部署；
- 版本标签：`v1.0.0-一期员工管理`；
- 本机无 JDK/MySQL/Redis：B/C 阶段验收为「代码完成 + 结构自检」，编译与运行验证集中在 M5（服务器或装环境后）。

### 2.4 一期技术栈清单（已确认）

后端：Java 17 + Spring Boot 3.x + MyBatis-Plus + Redis + JWT(jjwt 0.12.x) + EasyExcel + Flyway + Lombok + spring-boot-starter-validation + spring-security-crypto（仅 BCrypt）。
前端：Vue 3 + Vite + Pinia + Vue Router + Element Plus + Axios。
数据库：MySQL 8（默认）+ PostgreSQL 双脚本。

## 3. 二期（概要）

### 3.1 背景与目标

对接驿站包裹数据（约 20 万包裹量级），实现自动采集、入库与查询，让站长/员工在系统内看到本站包裹数据。

### 3.2 功能范围（概要）

| 模块 | 说明 |
| ---- | ---- |
| 同步任务管理 | 后端按驿站生成同步任务；任务状态机（待领取/执行中/成功/失败） |
| 爬虫微主机 | Python 3.12 + httpx；轮询 ECS 领取任务 → 调用多多买菜 API 抓取 → 数据回推 ECS |
| 包裹数据 | 按驿站/状态/时间筛选查询、分页浏览、基础统计 |
| 看板扩展 | 包裹量趋势、驿站维度排行 |
| 角色开放 | 正式启用 STATION_ADMIN（站长看本站数据），数据可见范围基于 `employee.station_id` |

### 3.3 技术方案要点（届时专项设计评审）

| 要点 | 方案方向 | 备注 |
| ---- | ---- | ---- |
| 爬虫接口组 | `/api/v1/crawler/*`，独立 API Key 认证（双认证体系：内部 JWT + 爬虫 API Key） | 与管理接口物理隔离 |
| 分布式锁 | Redis `crawler:lock:{station_id}`，防止同一驿站任务被并发领取 | SETNX + TTL |
| parcel 表 | 复合索引 `(station_id, status)`；唯一键 `station_id + waybill_no` 防重复入库；同步批次号留痕 | 预告见 [db.md](db.md) 6.2 |
| 大表查询 | 避免 `SELECT *` 与深度分页（游标分页 / 延迟关联）；20 万行单表 MySQL 可承载，重点是索引与查询模式 | 不提前分表 |
| 部署 | 微主机侧 Python 部署脚本（宝塔/systemd）；ECS 侧沿用一期部署模式 | 生产只拉 Git 代码 |

### 3.4 对一期的依赖（一期必须做对的事）

1. `station.code` 作为对接键（唯一 + 格式校验，二期冻结）；
2. `employee.station_id` 归属关系与索引（二期数据可见范围基础）；
3. Redis Key 前缀隔离约定（`hrm:` 与 `crawler:` 互不干扰）；
4. 统一响应/错误码分段（二期扩展 60xx 爬虫段、70xx 包裹段）。

## 5. 风险登记表

| 风险 | 影响 | 缓解措施 |
| ---- | ---- | ---- |
| 本机无编译环境，问题发现滞后 | 后端/前端缺陷在部署阶段集中暴露 | B17/C11 设为强制验证关口；B/C 任务验收标准写成可静态审查的明确条款 |
| 双库脚本漂移 | PostgreSQL 行为与 MySQL 不一致 | 脚本同源生成（db.md 为唯一基准）、E05 双库验证（P2 但脚本必须交付）、索引名带表前缀统一 |
| Excel 导入性能（BCrypt 逐行加密） | 1000 行导入超时 | 散列复用策略（决策 D4），设计阶段已规避 |
| 登录日志无限增长 | 看板查询变慢 | `idx_login_log_login_time` 索引兜底；归档策略二期评估 |
| 部分索引/方言差异导致的唯一性实现分歧 | 双库唯一性语义不一致 | 一期统一采用 Service 层查重（决策 D7），不依赖数据库特性 |
| 角色模型演进（二期站长） | 权限矩阵返工 | `role` 字段已预留 STATION_ADMIN；接口层角色白名单一处收口 |
| 20 万包裹数据规模 | 二期查询/写入瓶颈 | 已在 parcel 表设计要点中预研（索引/唯一键/分页模式），二期开工前专项评审 |

## 6. 发布流程（引用仓库规范）

1. 功能按模块在 `feature/*` 分支开发，自测后合入 `dev` 联调；
2. 验收通过后 `dev → main`，打 tag（一期 `v1.0.0-一期员工管理`）；
3. 服务器 `git pull origin main` → 编译打包 → 备份数据库 → 执行变更脚本（Flyway 随启动自动迁移）→ 重启服务；
4. 回滚方案：切换历史 tag 版本 Jar 包；数据库变更遵循 Flyway 版本纪律（只增不改）；
5. 每次上线后同步更新 `docs/` 与 `update-log.md`。
