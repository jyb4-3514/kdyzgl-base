## 1. 项目背景与一期定位

### 1.1 系统背景

「快递驿站智汇系统」服务于连锁驿站场景的内部管理，整体迭代路线为：

```text
一期 员工管理（本文档） → 二期 驿站数据同步（20 万包裹数据） → 三期 工单系统
```

### 1.2 一期定位

一期交付 **PC Web 管理端**（`hrm-admin`）+ **后端服务**（`hrm-server`），完成组织与员工基础数据底座：

1. 登录认证体系（JWT + Redis 会话）；
2. 员工全生命周期管理（含 Excel 批量导入导出）；
3. 部门（树形）与驿站管理，其中「员工归属驿站」是二期包裹数据同步的前置基础；
4. 管理端首页数据看板。

### 1.3 现状约束

- 仓库当前为空骨架（目录结构 + `.gitignore` + `env.example` + 5 个占位 `index.vue`），一期全部从零搭建；
- 开发机无 JDK/MySQL/Redis，本机无法编译验证，编译与运行验证统一在服务器（或装好环境后）进行，详见 [../TASK.md](../TASK.md) 使用说明；
- 部署环境为腾讯云 Linux + 宝塔，生产环境只拉取 Git 代码，配置外置于服务器磁盘。

## 3. 角色与权限

### 3.1 角色定义

| 角色编码 | 名称 | 说明 |
| ---- | ---- | ---- |
| ADMIN | 系统管理员 | 管理端全部功能；由 Flyway 种子数据初始化首个账号，后续可由管理员指定 |
| STAFF | 普通员工 | 一期仅可登录并维护本人信息（个人中心 + 修改密码），为二期/三期员工侧功能预留账号体系 |
| STATION_ADMIN | 驿站站长 | **一期不启用**，仅作为 `role` 字段预留值，二期驿站数据同步时开放 |

> 为什么一期只用两级角色：一期是管理端闭环，STAFF 的业务功能（看包裹、提工单）在二三期才存在。提前引入站长角色只会增加权限矩阵复杂度，收益为零。

### 3.2 权限矩阵

| 功能 | ADMIN | STAFF |
| ---- | ---- | ---- |
| 登录 / 退出 / 修改本人密码 | 可 | 可 |
| 个人中心（查看本人信息） | 可 | 可 |
| 首页数据看板 | 可 | 不可 |
| 员工管理（增删改查/启停/重置密码/导入/导出） | 可 | 不可 |
| 部门管理 | 可 | 不可 |
| 驿站管理 | 可 | 不可 |

### 3.3 鉴权机制概述

- 认证方式：JWT（HS256）+ Redis 会话，单 Token 方案，详见 [api.md](api.md) 第 3 章；
- 权限控制：后端接口按 `@RequireAdmin` 注解声明 ADMIN 专属接口，未授权返回 403；
- 前端控制：路由守卫按角色渲染菜单与拦截越权路由（前端控制仅为体验层，安全以后端为准）。

## 4. 功能清单（含优先级与验收标准）

优先级定义：P0 = 一期必须交付且验收不通过不能上线；P1 = 一期交付，可在上线后一周内补齐；P2 = 增强项，不阻塞上线。

### 4.1 F1 登录与账号

| 编号 | 功能 | 优先级 | 描述 | 验收标准 |
| ---- | ---- | ---- | ---- | ---- |
| F1-1 | 账号登录 | P0 | 用户名 + 密码登录；成功建立 Redis 会话并写入登录日志；失败也写入登录日志（含原因与 IP） | 正确账密进入系统；错误账密提示 1001；禁用账号提示 1002 且不创建会话；`login_log` 成败均有记录 |
| F1-2 | 退出登录 | P0 | 删除 Redis 会话 | 退出后原 Token 调用受保护接口返回 401 |
| F1-3 | 首登强制改密 | P0 | `pwd_changed=0` 的账号登录成功后强制进入改密页，完成前不可访问其他页面 | 种子管理员首登被引导改密；改密成功后重新登录方可进入系统 |
| F1-4 | 修改本人密码 | P0 | 校验原密码；新密码强度校验（8-20 位，含字母和数字）；修改成功后当前会话失效，需重新登录 | 原密码错误提示 1004；新密码不合规提示 400；改密后旧 Token 立即失效 |
| F1-5 | 个人中心 | P1 | 展示本人基本信息（手机号脱敏展示） | 本人信息与档案一致 |

### 4.2 F2 首页看板

| 编号 | 功能 | 优先级 | 描述 | 验收标准 |
| ---- | ---- | ---- | ---- | ---- |
| F2-1 | 数据看板 | P1 | 4 个指标卡片：员工总数、驿站数、部门数、今日登录数 | 数值与数据库统计口径一致（口径见 [api.md](api.md) 4.2）；STAFF 不可见该菜单且直接访问 URL 被拦截 |

### 4.3 F3 员工管理

| 编号 | 功能 | 优先级 | 描述 | 验收标准 |
| ---- | ---- | ---- | ---- | ---- |
| F3-1 | 分页查询 | P0 | 关键字（姓名/登录账号/手机号模糊）+ 部门（含子部门级联）+ 驿站 + 状态筛选，按创建时间倒序 | 各筛选条件组合正确过滤；分页参数正确生效；列表手机号脱敏展示 |
| F3-2 | 新增员工 | P0 | 录入账号、姓名、手机号（必填）及性别/部门/驿站/角色/入职日期/备注；密码必填 | 登录账号/手机号与活跃数据重复时分别提示 1003/2003；归属停用驿站提示 4004；新建账号可登录且首登强制改密 |
| F3-3 | 编辑员工 | P0 | 修改除登录账号外的资料；登录账号创建后不可修改 | 编辑后列表即时更新；账号字段只读；自我/最后管理员保护规则生效（见 5.4） |
| F3-4 | 删除员工 | P0 | 逻辑删除 + 强制下线 | 删除后不可登录、列表不可见；不能删除当前登录账号（2001）；不能删除最后一个可用管理员（2002） |
| F3-5 | 启用/禁用 | P0 | 禁用即时强制下线；启用恢复登录 | 禁用后存量 Token 立即 401；不能禁用自己/最后一个管理员 |
| F3-6 | 重置密码 | P0 | 管理员设定新密码；重置后强制下线且需首登改密 | 重置后旧密码失效、新密码可登录且被要求改密 |
| F3-7 | Excel 导入 | P1 | 下载模板 → 上传 .xlsx → 整批校验 → 全部通过才入库；错误一次性返回行级明细 | 见 5.5 导入流程验收与 [api.md](api.md) 第 5 章 |
| F3-8 | Excel 导出 | P1 | 按当前筛选条件全量导出 | 导出文件列与 [api.md](api.md) 第 6 章一致；数据与筛选结果一致；手机号完整（见决策 D5） |

### 5.3 登录与首登强制改密流程

```text
访问任意页面
   ↓ 路由守卫：无 Token → /login
登录页输入账号密码
   ↓ POST /api/v1/auth/login
   ├─ 失败：提示（1001 用户名或密码错误 / 1002 账号已禁用），停留登录页
   └─ 成功：保存 Token 与用户信息
        ↓ 判断 pwd_changed
        ├─ false → 强制进入 /profile 改密卡片（路由锁死，不可跳转其他页面）
        │           ↓ 改密成功 → 清除登录态 → 回登录页 → 用新密码重新登录
        └─ true  → 按角色落地（ADMIN → /dashboard，STAFF → /profile）
```

### 5.4 账号状态联动规则（后端强制）

| 触发动作 | 联动效果 |
| ---- | ---- |
| 禁用员工 | 删除该账号 Redis 会话（存量 Token 立即失效） |
| 删除员工（逻辑删除） | 同上 + 账号不可再登录 |
| 重置密码 | 同上 + `pwd_changed` 置 0（下次登录强制改密） |
| 修改本人密码 | 删除本人会话，需重新登录 |
| 同账号再次登录 | 覆盖旧会话（单会话策略，旧 Token 失效，即"互踢"） |
| 自我保护 | 不允许对当前登录账号执行：禁用 / 删除 / 重置密码 / 角色降级（错误码 2001） |
| 最后管理员保护 | 不允许对最后一个可用 ADMIN 执行：禁用 / 删除 / 角色降级（错误码 2002） |

### 5.5 Excel 导入流程

```text
员工管理页 → 「导入」按钮
   ↓ 1. 下载模板（接口动态生成，仅表头 + 批注说明，不含示例数据行）
   ↓ 2. 按模板填写（列定义与校验规则见 api.md 第 5 章）
   ↓ 3. 上传 .xlsx（≤ 10MB，数据行 ≤ 1000）
   ↓ 4. 后端整批校验（逐行逐字段收集错误）
   ├─ 存在任意错误 → 全部不入库，返回 5003 + 行级错误清单
   │                  前端弹窗展示：行号 / 字段 / 原因
   │                  管理员修正文件后原样重导（操作可重复，无半成功状态）
   └─ 全部通过 → 事务批量入库，返回成功条数
```

导入默认值：`role=STAFF`、`status=1`、`pwd_changed=0`、初始密码为服务器配置 `hrm.employee-init-password`（占位 `change_me_init_password`，首登强制改密）。

### 5.6 通用交互约定

- 删除、禁用、重置密码等危险操作必须二次确认；
- 所有写操作成功/失败有明确反馈（Element Plus Message）；
- 表格请求期间展示 loading；空数据展示空态；
- 分页默认 10 条/页，可选 10/20/50。

## 6. 非功能需求

### 6.1 安全

| 项 | 要求 |
| ---- | ---- |
| 密码存储 | BCrypt（`$2a$`，cost=10），任何接口不回传密码与散列 |
| 传输认证 | JWT HS256，密钥 ≥ 32 字节随机串，存服务器配置（占位 `change_me_jwt_secret_*`） |
| 会话控制 | Redis 集中管理，支持登出 / 互踢 / 强制下线（见 5.4） |
| 敏感字段脱敏 | 手机号在所有 JSON 出参中脱敏（规则见决策 D5），日志中严禁打印密码/Token/手机号 |
| 输入校验 | 所有接口入参做 Bean Validation 校验，非法参数返回 400 与明确提示 |
| SQL 注入 | MyBatis-Plus 全参数化查询，禁止字符串拼接 SQL |
| 越权防护 | ADMIN 接口统一 `@RequireAdmin` 拦截；路径资源归属校验（如编辑目标是否存在） |
| CSRF | Token 置于 Authorization 头（非 Cookie），天然免疫 CSRF |
| 配置安全 | 真实密钥只存服务器磁盘，仓库仅 `env.example` 模板与 `change_me_*` 占位 |
| 上传安全 | 导入仅接受 .xlsx，大小 ≤ 10MB，数据行 ≤ 1000 |

### 6.2 性能

| 指标 | 目标 |
| ---- | ---- |
| 员工列表查询（5000 行内） | P95 < 500ms |
| 看板统计 | P95 < 500ms |
| Excel 导入 1000 行 | < 5s（依赖散列复用策略，见决策 D4） |

### 6.3 兼容性与可维护性

## 7. 关键设计决策记录（含理由）

### D1 员工即账号（employee 表含 username/password/role）

**决策**：不建独立 `sys_user` 表，员工档案直接携带登录凭证与角色。

**为什么**：
1. 一期全部功能围绕员工档案展开，独立账号表需要「员工-账号」双向同步与跨表唯一性校验，复杂度高、收益为零；
2. 账号生命周期与员工入职/离职天然一致：删除员工即注销账号，禁用员工即冻结账号，无状态漂移；
3. 二期开放 STATION_ADMIN、三期员工侧功能，均可在 `role` 字段上直接演进，无需迁移数据。

**种子管理员**：由 Flyway `V2__init_data.sql` 初始化（部门「总公司」+ 账号 `admin`）。初始密码为部署占位值 `change_me_admin_init_password`（实际值部署时确定，绝不入库入仓），其 BCrypt 散列固化在种子脚本中；配合 `pwd_changed=0` 首登强制改密形成双保险。

### D2 Flyway 双库策略

**决策**：迁移脚本按数据库方言分目录存放，`spring.flyway.locations=classpath:db/migration/{vendor}` 自动选择：

```text
hrm-server/src/main/resources/db/migration/
├── mysql/V1__init_schema.sql      V2__init_data.sql
└── postgresql/V1__init_schema.sql V2__init_data.sql
```

**为什么**：`{vendor}` 是 Flyway 原生占位符，按实际连接的数据库自动选目录，切换数据库零代码改动；两个目录从源头隔离方言差异，避免在单脚本里写「两种库都能跑」的畸形 SQL。同时按仓库规范在 `hrm-dev/sql/schema/{mysql,postgresql}/` 维护结构快照供评审（执行以 Flyway 目录为准）。

### D3 单 Token + Redis 会话（不用双 Token）

**决策**：仅签发一个 JWT（24h 固定有效期），登录态集中存 Redis：`hrm:session:{employeeId}` → `{jti, username, role, loginIp, loginTime}`，TTL 与 Token 一致。

**为什么**：
1. 双 Token（access + refresh）引入续期竞态、刷新撤销、多套存储键，是为「无状态大规模开放 API」设计的方案；一期管理端需要的是「可注销、可强制下线、可控有效期」，单 Token + Redis 会话一行 `DEL` 即可满足；
2. Token 内含 `jti`，会话比对 `jti` 即可实现「同账号新登录顶掉旧会话」（互踢），并天然支持禁用/删除/重置密码的即时下线；
3. 固定 24h 不做滑动续期：避免长尾会话永不过期与续期实现复杂度，管理端每日登录一次符合使用习惯。详细机制见 [api.md](api.md) 第 3 章。

### D4 Excel 导入：整批校验 + 行级错误一次性返回 + 散列复用

**决策**：导入采用「整批校验，全部通过才入库（事务）」；任何行错误都以 `[{row, field, message}]` 一次性返回；初始密码相同的行复用同一次 BCrypt 计算结果。

**为什么**：
1. 逐行入库会产生「半成功」状态，管理员必须手工剔除已导入行再重导，极易造成重复或遗漏；整批失败 → 修正文件 → 原样重导，操作幂等可重复；
2. 性能陷阱规避：BCrypt 单次约 100ms，1000 行逐行加密需 100 秒以上；由于导入账号初始密码统一，散列只需计算 1 次复用 1000 次，导入耗时从分钟级降到秒级（安全性由首登强制改密兜底）。

### D5 手机号脱敏规则

**决策**：
- 规则：11 位手机号显示为 `138****5678`（前 3 后 4）；非 11 位号码显示前 3 位 + `****`；
- 范围：**所有 JSON 出参一律脱敏**（列表、详情、个人中心，含本人查看自己）；
- 例外：**Excel 导出保留完整手机号**。

**为什么**：JSON 接口是日常高频读取通道，脱敏防止敏感信息在页面、缓存、日志中扩散；而导出是管理员显式发起的批量数据操作（通讯录/线下档案用途），脱敏导出会使该功能失去存在意义。导出操作至少可通过登录日志追溯到操作者。若后续合规要求收紧，只需在导出列统一接入脱敏工具类，改动收敛在一处。
