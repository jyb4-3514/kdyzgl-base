## 3. 形式核对结论

### 3.1 结论

**不构成新增暴露面**（即：文档层出现该生产域名**不构成实质安全暴露面问题**）。定性为**规范一致性问题**（违反 ADR 文首自设声明、与 split-plan §2.4 口径冲突），**非安全漏洞、非可利用风险**。

### 3.2 依据（按四项判据）

| 判据 | 事实 | 判定 |
| --- | --- | --- |
| **对外可访问性** | 该域名是对外提供服务的**公开主域名**，公共 DNS 可解析（`demo-docker-deploy.md` 记有 A 记录）、HTTPS 站点公网可达（同文件记线上 200）。域名本身非秘密，第三方经 DNS 查询 / 证书透明度（CT）日志即可获得。 | 域名属**公开信息**，非敏感标识 |
| **信息来源独立性** | 同一域名已记载于仓库 `AGENTS.md`（新会话入口，自动注入）、`.trae/rules/项目规则1.md`、`.github/CONTRIBUTING.md`、`SESSION-STATE.md` 及多份 `hrm-dev/docs/**`（第 14 项）。ADR v1 的出现系**同一已知信息的重复**。 | 未新增任何差异化 / 独立可得的信息 |
| **是否与凭据组合成攻击链** | ADR 全文凭据 / 真实 IP / AppKey **命中 = 0**（第 1–13 项）；同文件内**无与域名配对的账号口令、密钥、内网拓扑**。 | 域名不与凭据组合 → **不构成攻击链**；据此获得的信息不超过公开 DNS 已提供的信息（增益 ≈ 0） |
| **行业惯例 / 等保口径** | 等保与通用安全基线（全局规则 §4）的保护对象为：**凭据、密钥、生产源码与 `*.map`、内网地址与拓扑**；对外服务的**公开域名**一般等同企业官网地址，不计入敏感信息。 | 不构成安全红线违规；属**文档自设声明**的规范偏差 |

### 3.3 附带判定

- **不属高危**：无凭据泄露痕迹、无可利用漏洞、无攻击链。按 `项目规则1.md` 冲突裁决表「安全风险判定 vs 进度」，**无需升级用户裁定**。
- **风险等级：低（规范类）**。
- ADR v2 已按必改项 2 修订到位，该历史残留的**增量信息暴露 ≈ 0**，且已在 ADR 层闭环。
