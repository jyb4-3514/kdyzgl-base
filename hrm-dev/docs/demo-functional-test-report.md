### 1.4 规避桩说明（重要，影响结论适用范围）

`e2e/utils/harness.js` 的 `shimViteVirtualModules()` 在**浏览器侧**为两个被中间件破坏的 Vite 虚拟模块补齐内容：

| 请求 | dev server 实际返回 | 规避桩行为 | 理由 |
| ---- | ---- | ---- | ---- |
| `/@vite/client` | `200 text/html`（pc.html 内容） | 返回与 Vite 行为等价的最小实现（`createHotContext/updateStyle/removeStyle/injectQuery`） | 该模块内容由 Vite 生成、非业务代码；缺失会使 SFC 的样式注入 import 失败 |
| `/@id/__x00__plugin-vue:export-helper` | `200 text/html`（pc.html 内容） | 返回 plugin-vue 的稳定 helper 源码 | 同上 |
| `**/*vconsole*.js*` | dev 下真实加载 | 返回空实现 | vConsole 悬浮按钮会拦截右下角按钮点击（实测 A4-4），属开发调试工具，非被测功能 |

**适用范围**：全部功能、兼容性、性能结论均在装载上述桩的前提下取得；`e2e/00-dev-server.spec.js` 不装载任何桩，用于独立取证 P0-1。移动端与网页端的业务逻辑（路由、Mock、表单、图表）不受桩影响。

## 9. 结论与改进建议

### 9.1 结论

- **不可交付（当前 dev 环境）**：P0-1 未修复前，网页端与移动端入口白屏，演示主线无法进行。
- **修复 P0-1 后：三端功能与六档视口兼容性通过**；37 条用例 34 通过，未通过项中 2 条为 P0-1 自身取证、1 条为环境抖动。
- 本轮发现的 P1-1 / P1-2 / P2-1 在会话内已被并发开发修复并通过回归，**但仍需在 P0-1 修复后的干净环境复跑确认**。

### 9.2 改进建议（按优先级）

1. **修 P0-1（最高优先级）**：让 `hrm-demo-history-fallback` 只处理「HTML 导航请求」，至少放过 `/@`、`/@id/`、`/node_modules/`、`/src/`、`/@fs/` 前缀，或改为「仅当 `Accept` 含 `text/html` 且路径无扩展名」时回退。修复后 `e2e/00-dev-server.spec.js` 应自动转绿，可作为验收证据。
2. **弱网优化（生产态口径）**：PC 入口在慢网下首屏超 2 分钟，根因是 dev 未打包；生产侧应复核 `dist` 的按需引入与分包（既有台账记录 pc 首屏 gzip 451KB → 目标 250–290KB）。
3. **Mock 会话持久化回归**：新增的 `sessionStore.js` 需补一条契约断言（登录 → 重建 db → 旧 token 仍可通过 jti 校验），避免再次出现「刷新即掉线」。
4. **离线兜底**：为动态 `import()` 路由加统一失败处理（提示 + 重试入口），并把「懒加载失败」纳入全局错误采集（M11 的 `clientLog` 已有通道）。
5. **dev 工具干扰**：vConsole 悬浮按钮会遮挡右下角操作，建议在演示模式下默认不挂载或改为可折叠到边缘，避免演示现场误点。
6. **补 OBS-1 的根因确认**：给 `/attendance/summary` 加一次空数据/慢返回的契约用例，明确「`—` 是否代表取数失败」。
