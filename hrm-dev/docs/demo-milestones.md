## 三、进度跟踪机制（四载体）

| 载体 | 路径 | 作用 | 更新时机 |
| ---- | ---- | ---- | ---- |
| 里程碑台账 | `hrm-dev/docs/demo-milestones.md`（本文件） | 里程碑级状态与验收 | 每个里程碑状态变更时 |
| 会话检查点 | `SESSION-STATE.md` | 跨会话恢复：进度、决策、遗留、实测结论 | 每个子任务完成后 |
| 可执行验收 | `hrm-dev/hrm-demo/scripts/verify-mock.mjs` | **断言总数即契约完成度**（当前基线 347） | 每批契约变更 |
| 构建验收 | `npm run build` | 可交付性（EXIT=0 + 三入口产物齐全） | 每批实现完成 |

**度量口径**：
- 契约完成度 = 断言总数 / 目标断言数
- 实现完成度 = 已落地页面数 / 规范清单页面数
- 交付就绪 = `verify:mock` 全绿 **且** `build` EXIT=0 **且** M3/M4 全部完成

**检查点纪律**：每完成一个子任务，立即回填 `SESSION-STATE.md` 一行摘要，对话中不再保留过程细节（长线任务防上下文爆炸）。

## 四、变更控制

1. M1 冻结后，视觉/交互方案变更须由主智能体评审，并回写 `demo-ux-improvement.md` 版本说明
2. M2 冻结后，契约变更（路径/字段/错误码）须由主智能体批准，并同步更新 `demo-design.md` 错误码节
3. 严禁实现方私自扩展契约字段；如需新字段，先改契约再改实现
4. 一期资产 `hrm-admin/`、`hrm-server/` 全程零改动，删除 `hrm-demo/` 即可完全回滚
