## 1. 问题（现状与证据）

现状：`express-station-ops-engineer` 在无外部派活时**零动作**（使用者描述为「躺平」）。成因如下：

| # | 成因 | 证据（可核） |
| --- | --- | --- |
| 1 | **职责域只有「执行」，无自驱面**——唯一职责是部署执行 / CI-CD / 宝塔 Nginx / 监控回滚，均落 C 档，须等主智能体三步授权；MCP 归主智能体独占，连只读查服务器都不做 | `.trae/agents/express-station-ops-engineer/SKILL.md` §职责边界；`项目规则1.md` §10.3 §10.5 |
| 2 | **无例行职责，无周期性可交付物**——产物仅「部署记录 / 运维脚本」，均为事件驱动 | 同上 §输入与输出契约 |
| 3 | **配置命令与 `deploy.md` 记载的任一流程均不一致（硬伤）**——SKILL.md 阶段 2 用 `cd /www/wwwroot/kdyzgl`、`cp target/*.jar /www/wwwroot/kdyzgl/app.jar`、`systemctl restart kdyzgl-server`；而 `deploy.md` 记载的仓库路径为 `/www/wwwroot/kdyzgl-base`，服务/产物为 `hrm-server` 与 `/www/wwwroot/hrm-server/hrm-server.jar`，现网变更载体与站点根见 §11 | `.trae/agents/express-station-ops-engineer/SKILL.md` 阶段 2；`deploy.md` 第 45–51 行、第 484–553 行、§11 |
| 4 | **现网真实运维面缺失**——`/data` 数据盘约束（系统盘 30G / 数据盘 50G）、hids 日志无保留策略曾 19 天累积 4.7G、宿主 MySQL 端口 3307 与 UFW 定向放行，均未写入角色配置 | `deploy.md` 第 79–103 行（数据盘分工、端口切换、增长点治理） |

> 成因 3 属**风险**而非仅效率问题：该角色一旦被唤起，将按文档中不存在的路径与服务名执行。

| # | 验收项 | 判定方式 |

| --- | --- | --- |

### D. 免 MCP 条件下的工作方式（§10.5 不变）

产出「**操作清单 + 待执行命令脚本**」：命令不含真实凭据（用 `change_me_*` 占位），由主智能体代发执行；执行结果回传后归档为部署记录或巡检报告。

### E. 降级路径（v2 新增）

| 情形 | 处置 |
| --- | --- |
| 主智能体未代发命令 / 命令执行失败 | 巡检报告对应项以「**未获取（原因）**」占位，并附**手工核实步骤**；不得静默跳过 |
| 无法取得实测值 | 一律标注「**未验证**」，禁止推断或填写估计值（`项目规则1.md` §4.1） |
| 某服务不可达 | 结论收敛到「静态审查 + 该服务未获取」，不阻塞其余 5 项巡检 |

## 4. 替代方案对比（v2 新增）

| 方案 | 内容 | 取舍理由 |
| --- | --- | --- |
| **方案一（采纳）** | 扩职责域 + 例行巡检 + 命令修正 + 免 MCP 工作方式 | 在不触碰权限边界的前提下解决「无自驱面」与「命令失真」两个根因；改动限于配置与文档，可 `git` 整体回滚 |

| 方案三（否决） | 不改配置，仅靠主智能体多派活 | 不解决成因 1/2（授权依赖与无例行产出），问题原样保留；且成因 3 的命令失真仍在 |
| 方案四（否决） | 新设「运维巡检」独立角色 | 与运维工程师职责重叠，编制从 10 增至 11 而产出未增；违反核心原则 2「精简优先」 |
