## 1. 问题（现状与证据）

`express-station-security-engineer` 当前**只有事件驱动职责**——威胁建模 / 代码与配置审计 / 依赖与供应链核查 / 攻击面验证 / 合规判定，全部由外部派活触发；**无例行职责，无周期性可交付物**。

证据：`.trae/agents/express-station-security-engineer/SKILL.md` §输入与输出契约 —— 下游输出仅「安全评估报告 `security-{主题}.md`」「C 档技术结论」「安全测试用例」，均事件驱动，无按日/按周产出。

后果：**无人派活即零动作**；而依赖漏洞、暴露面漂移、证书与私钥落点、日志异常迹象这类问题**随时间劣化**，不巡检就静默累积。

> **与运维侧的对称性**：运维侧已由 `ops-agent-optimization.md`（v2.2 及以后，现 v2.3）补齐「例行巡检与容量治理」（A 档只读、每天一次 + 每次部署后一次）。本方案补齐安全侧，形成**运维看可用性与容量、安全看风险与暴露面**的分工，两者**并行不互替**（调度规则 §9「安全面 vs 工程面」）。

## 2. 目标与验收标准

**目标**：让网络安全工程师在**不依赖 C 档授权、不获取真实凭据明文**的前提下拥有每日可自驱的风险巡检产出；发现高危一律停下回报，不越界处置。

| # | 验收项 | 判定方式 |
| --- | --- | --- |
| V1 | 巡检清单 **6 项结构齐全**，每项含「检查对象 / 命令或核对面 / 判定阈值 / 异常处置」四要素 | 逐项核对四要素 |
| V2 | 权限声明明确「巡检 = A 档只读；**需生产环境做侵入性/破坏性验证必须停下请示**」 | 与 §10、本角色既有硬红线逐条比对 |
| V3 | 巡检报告命名 `security-checkup-{YYYYMMDD}.md`，不与 `security-{主题}.md`、`ops-checkup-*.md`、`review-*.md`、`tech-review-*.md` 冲突 | 与现有命名比对 |
| V4 | 未新增 MCP 直调权限、未改 §10 权限四档、**未削弱** §7.2（含第 5 条）任何一条硬红线 | 与 §7.2、§10.4、§10.5 逐条比对 |
| V5 | 明确「不得在巡检中读取真实凭据明文」「未验证不得声称已确认合规」（沿用既有硬红线，不得放宽） | 文本核对 |
| V6 | 凡引用现网事实处，均给出仓库出处（文件 + 行号）或显式标注「未验证」 | 逐条检查引用 |
| V7 | **与运维巡检无重复判定**：证书剩余天数仅由运维 A4 判；**本方案不得出现任何 `≤N 天` 形式的证书剩余天数数值阈值** | ① 交叉比对 `ops-agent-optimization.md` §3.A；② **机械核对**：在本文件中检索 `≤\s*\d+\s*天` 且上下文含「证书剩余」，应 **0 命中** |

## 3. 改动清单

### A. 职责域新增「例行安全巡检」子域（A 档只读）

六项固定巡检（每天一次）：

| # | 巡检项 | 检查对象 / 核对面 | 判定阈值 | 异常处置 |
| --- | --- | --- | --- | --- |
| S1 | 依赖与供应链 | `hrm-dev/hrm-server/pom.xml`、前端与 Demo 的 `package.json` / lock；依据**官方公告 / CVE**核查 | 出现官方标定的高危/严重漏洞 | 出修复建议（含版本与验证方式）→ 交后端/前端；**无权威渠道时标「不确定」**（见 §1.1 L2、核心原则 1） |
| S2 | 配置与占位残留 | `change_me_*` 残留（`deploy.md:553` 已由部署脚本强校验）、外置配置权限、`.gitignore` 覆盖、凭据是否入库 | 存在残留 / 凭据入库痕迹 | 属 §7.2 红线 → **立即停下回报主智能体** |
| S3 | 对外暴露面 | 8080 / 3306 / 6379 是否**对公网**开放、生产 `*.map` 是否 404（§10.4 红线）、HTTPS 强制跳转、调试端点 | 任一端口对公网开放 / `.map` 可达 | `.map` 公开属 D 档红线 → 立即停下；端口公开出建议交运维（改防火墙属 C 档） |
| S4 | 鉴权与越权回归 | JWT 校验链路、写操作数据归属校验点、未授权接口可达性 | 未授权可写 / 可跨站访问他人数据 | 出复现步骤与修复建议 → 交对应实现角色；**只做只读探测，不构造攻击载荷** |
| S5 | 日志异常迹象 | 认证失败 / 账号锁定记录、异常 UA / IP 聚集、暴力破解迹象（只读；范围见 §1.1 L3） | 短时高频失败或异常聚集（阈值暂定，`TODO(扩展)`） | 出风险登记与缓解建议；**不封禁、不改配置**（属 C 档） |
| S6 | 证书与私钥**落点与权限** | 证书与私钥存放位置、文件权限、是否明文可访问 | 私钥可被非授权主体读取 | 落点/权限问题 → 立即停下回报主智能体 |

**两项分工注（划界，避免重复判定或双不管）**：

- **S6 ↔ 运维 A4**：**证书剩余天数（可用性 / 续期状态）由运维 A4 唯一判定**，本方案 S6 **只判落点与权限安全**，不重复、不代判、不引入该阈值。
- **S3 ↔ 运维 A2**：**运维 A2 判「容器健康 + 8080 单一托管」（可用性/双进程）**；**S3 判「对外暴露面」（端口是否对公网开放、`.map` 是否可达、HTTPS 强制）**。同一事实各自出本域结论，不越界代判。

### B. 新增周期性产物

`hrm-dev/docs/security-checkup-{YYYYMMDD}.md`：六项固定表（检查项 / 实测或核对结果 / 阈值 / 结论 / 处置建议）+ 风险登记（严重级 / 可利用性 / 影响面）+ 遗留 TODO。

- **周期**：每天一次（与运维巡检错开执行时刻）。
- **权限**：A 档只读；数据由主智能体代发命令采集（§10.5 MCP 主智能体独占）。
- 与既有 `security-{主题}.md` 的区别：后者是**事件驱动的深度评估报告**（含威胁建模与复验结论），本产物是**日频轻量巡检表**，**不替代**前者。

### C. 噪声控制（可判定措施）

| # | 措施 | 判定标准 |
| --- | --- | --- |
| N1 | **只报变化与越阈** | 仅「与上次基线相比发生变化」或「越过阈值」的项进入**异常项汇总**；未变化项只留在明细表 |
| N2 | **持续项降级** | 连续 ≥7 天同类异常且无升级（严重级未变）→ 降级为「持续观察」，不再计入异常数量 |
| N3 | **摘要可比** | 报告头部固定输出一行「本次异常项数 / 上次异常项数 / 新增项」，便于跨日比对 |

### D. 降级路径

| 情形 | 处置 |
| --- | --- |
| 命令未代发 / 执行失败 | 对应项以「**未获取（原因）**」占位 + 手工核实步骤；不得静默跳过 |
| 无法取得实测值 | 标「**未验证**」；**不得声称「已确认合规」**（§7.2 第 5 条既有硬红线） |
| 需在生产环境做侵入性 / 破坏性验证 | **一律停下请示主智能体**，不得自行执行（既有硬红线，不放宽） |

## 4. 替代方案对比

| 方案 | 内容 | 取舍理由 |
| --- | --- | --- |
| **方案一（采纳）** | 给现有安全角色加**日频只读巡检**子域 | 补上「无例行产出」根因；复用既有角色与技能，编制不变；改动限于角色配置与文档，可 `git` 整体回滚 |
| 方案二（否决） | 新设独立「安全巡检」角色 | 与 §4.9 网络安全工程师职责重叠，编制从 10 增至 11 而产出未增；违反核心原则 2「精简优先」 |
| 方案三（否决） | 不巡检，维持纯事件驱动 | 依赖漏洞 / 暴露面漂移 / 落点劣化均随时间累积且无人发现，问题原样保留 |
| 方案四（否决） | 把安全巡检并入运维巡检（运维一并查安全） | 违反调度规则 §9「安全面 vs 工程面」与 §10.3 A08 反模式：**运维不承担任何一类安全评估**，安全实质结论归网络安全工程师 |

## 5. 明确不改（边界）

- **不给 MCP 直调权限**（§10.5 主智能体独占）。
- 不改 §10 权限四档定义。
- **不削弱任何既有安全红线**，逐条保留并纳入本子域约束：不逆向接口签名、不注入进程、不伪装设备标识、不绕过风控限频（§7.2 第 5 条）；不在生产库执行破坏性验证（§10.4）；报告中不得出现真实凭据明文（§7.1）；**未验证项闭环前不得声称「已确认合规」**（§7.2 第 5 条）；**不得以「以 root 运行应用进程」为前提给出放行结论**（§10.4）；**不获取、不轮换凭据**（§7.1，凭据归主智能体托管）。
- **不做审批 / 授权**（C 档授权归主智能体 §10.3），**不执行修复**（只出建议与验收标准）。
- 不改 Nginx / 宝塔配置，只出建议交运维。

| # | 风险 | 处置 / 登记 |
| --- | --- | --- |
| I1 | 本子域**授予被改角色每日只读接入生产**，存在「自我扩张」的独立性缺口 | **该变更涉及的安全实质结论（是否可接受每日只读接入）由用户 2026-09-25 裁定**，**不由被改角色自评**；本方案仅登记裁定来源，不代出安全结论 |

| I3 | 巡检发现「需在生产环境做侵入性验证」时可能越界 | 沿用既有硬红线：**一律停下请示**，不由本角色自行判定放行 |

## 7. 风险、回滚与假设

**风险**：纯角色配置与文档改动，无运行时影响。主要风险为「日频巡检噪声」（见 §3.C 控制措施）与「误把未获取项当结论」（见 §3.D）。

**回滚**：`git checkout -- <被改文件>`；不涉数据、不涉服务。

**假设与待确认**：

| # | 假设 / 待确认 | 处置 |
| --- | --- | --- |
| H1 | 巡检为**每天一次**，经 TRAE 定时任务触发 | **用户 2026-09-25 裁定**（运维 07:00 / 安全 07:30） |
| H2 | 允许经 SSH / 宝塔 MCP **只读**接入生产采集数据 | **用户 2026-09-25 裁定** |
| H3 | 数值阈值：S5 的「短时高频失败」聚集阈值**暂定**；证书剩余天数**不由本方案判定**（归运维 A4） | 暂定值标 `TODO(扩展)`，待用户确认 |
| H4 | 本方案不改动 `hrm-demo` / 生产工程代码 | 与 §12.1 一致 |
| H5 | 定时任务仅在到点时 IDE 在运行才执行；本机不在线则当日不产生报告 | 已在交付说明中显式声明，**不构成「保证每天必跑」** |
