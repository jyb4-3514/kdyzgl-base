# 三期企业微信接入 · 第一批 POC 执行手册

> 适用对象：能在驿站采集端 Windows 10 机器上点鼠标、复制粘贴命令的**非开发人员**
> 依据文档：`hrm-dev/docs/wecom-integration-adr.md`（下称 ADR）第 7 章 POC 计划、第 14 章安全合规红线、第 19/20 章待验证项与风险登记
> 本手册只描述**怎么执行、看什么、怎么回传**；结论回填用 `结果回填模板.md`
> 重要前提：本批 POC 的脚本**只在开发机做过语法级自检，从未在目标机运行过**（详见第 8 章「开发机未验证项清单」）。执行中的所有结论以目标机实测为准。

## 0. 一页速览

| POC | 目的 | 是否发消息 | 脚本（本目录） | 产出文件 |
|----|----|----|----|----|
| POC-01 | 企微 PC 客户端是否暴露 CDP 调试端口（决定读取路线 R1 是否可行） | 否 | `POC-01-探测调试端口.ps1` | `POC-01-结果.json` |
| POC-02 | UI Automation 能否读到群消息文本（决定读取路线 R2 是否可行） | 否 | `POC-02-UIA读群消息.ps1`（主）/ `POC-02-UIA读群消息.py`（备） | `POC-02-结果-第1次.json`、`POC-02-结果-第2次.json` |

## 2. POC-01：企微 PC 客户端是否暴露 CDP 调试端口

### 2.1 前置条件
- 企业微信已登录、正在运行（想更保险可先以**管理员身份**打开 PowerShell，只有管理员才能读到企微进程的完整模块列表）。
- 已知晓：带调试端口重启会**关闭当前企微**再重新打开（脚本会在执行前二次确认）。

### 2.2 第一步：只读探测（不发消息、不重启，先跑这个）
```powershell
cd D:\yizhan\hrm-dev\poc\wecom
powershell -NoProfile -ExecutionPolicy Bypass -File ".\POC-01-探测调试端口.ps1"
```

**预期现象**（控制台示例）：
```
==== POC-01 企微 CDP 调试端口探测 ====
[定位] 进程数=1 | 安装目录=... | 主程序=...
[特征] 模块枚举方式=dotnet | CEF 特征命中=True/False | 命中模块=...
[探测] 只读模式，探测 http://127.0.0.1:9222 ...
verdict = INCONCLUSIVE
```
- **只读模式通常就是 `INCONCLUSIVE`，这是正常的**（没带调试端口启动，端口当然大概率不通）。它主要是把「安装路径 / 版本号 / CEF 特征模块」这些信息先采集下来。
- 若这一步 `进程数=0`：请确认企微已登录且进程在运行；若模块枚举显示访问被拒，改用管理员身份重跑。

### 2.3 第二步：带调试端口重启并探测（关键步骤）
**执行前请先手动关闭企业微信**（脚本也会尝试关闭，但手动关闭更干净）。

```powershell
cd D:\yizhan\hrm-dev\poc\wecom
powershell -NoProfile -ExecutionPolicy Bypass -File ".\POC-01-探测调试端口.ps1" -Launch
```
脚本会提示确认：
```
即将执行【关闭当前企业微信 → 以 --remote-debugging-port=9222 重新启动】。
该操作不修改安装目录、不写注册表；关闭该实例并用正常方式重开企微即可完全恢复。
确认执行？输入大写 Y 继续，其他任意键取消
```
输入 `Y` 回车。

若首次未列出 target，可追加参数再试一次（部分 Chromium 版本需要它才允许附着）：
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\POC-01-探测调试端口.ps1" -Launch -ExtraArgs "--remote-allow-origins=*"
```

**预期现象（成功）**：
```
[结果] /json/version HTTP=200 | /json/list HTTP=200 | target 数>=1
verdict = PASS
```
**预期现象（失败）**：
```
[结果] /json/version HTTP=无响应 | /json/list HTTP=无响应 | target 数=0
verdict = FAIL
```

### 2.4 通过判据 / 失败判据（照抄 ADR 第 7 章）
- **通过判据**：能列出 target 且能 attach；能读到会话列表相关 DOM/可访问性节点。
- **失败判据与切换**：无法启动或端口不可用 → **R1 不成立**，转 POC-02；若两者均失败 → G1/G2 无解，触发 Q7。

> 说明：本脚本能自动判定到「端口可用 + 列出 target」这一层；「attach 并读到 DOM」属于 R1 的后续实现验证，不在本脚本范围，需在回填模板中标明为「待后续验证」。

### 2.5 回滚 / 中止
- **中止（执行前）**：在确认提示处**不要输入 `Y`**（输入任意其他键即取消）。
- **回滚（执行后）**：关闭本次带调试端口启动的企微实例 → 用正常方式（开始菜单 / 桌面快捷方式）重新打开企业微信，**即完全恢复**。
- 该操作**不产生任何持久化改动**：不修改安装目录、不写注册表、不加开机项。

## 3. POC-02：UI Automation 能否读到群消息文本

### 3.1 前置条件
- 企业微信已登录，且**打开一个含历史消息的群/会话并保持窗口可见**（不要最小化到托盘；不要停在空白的新会话）。
- 若群消息很少，先手动在该群发几条测试消息，让消息区有内容可读。
- **建议用 Windows PowerShell 5.1 运行主方案**（零安装）。Python 备用方案需 `pip install pywinauto`，**需安装第三方包，可能不被目标机策略允许**，优先不要用。

### 3.2 执行步骤（主方案，零安装）
第 1 次（冷启动前）：
```powershell
cd D:\yizhan\hrm-dev\poc\wecom
powershell -NoProfile -ExecutionPolicy Bypass -File ".\POC-02-UIA读群消息.ps1" -RunIndex 1
```
然后**冷启动企微**：完全退出企业微信（右下角托盘右键退出，确认进程结束），再重新打开并登录，打开同一个群。

第 2 次（冷启动后）：
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\POC-02-UIA读群消息.ps1" -RunIndex 2
```

**建议同时另存一份"更保险版"**（文本只留长度、不留内容）：
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\POC-02-UIA读群消息.ps1" -RunIndex 1 -RedactMode full
```
（`-RedactMode full` 会把消息文本替换成 `<TEXT len=数字>`，用于你完全不想让任何消息正文进入 Git 的场景。默认 `alias` 模式会保留**截断 60 字并脱敏**后的文本，用于证明"确实读到了文本"。）

### 3.3 预期现象
```
==== POC-02 UIA 读群消息（第 1 次） ====
[环境] Windows PowerShell 5.1 | .NET UIA 可加载=True | Python=...
[窗口] 企微进程数=1 | 顶层窗口数>=1
==== 结论（第 1 次）====
verdict = PASS / INCONCLUSIVE / FAIL
sessionListFound=True | sessionItems=n | messageAreaFound=True | messageSamples=m | inputBoxFound=True
treeDepth=.. | nodeCount=..
```
- 判断依据看两个布尔：`sessionListFound`（是否识别到会话列表）与 `messageAreaFound`（是否取到消息文本）。

### 3.4 通过判据 / 失败判据（照抄 ADR 第 7 章）
- **通过判据**：能稳定取到**消息文本**与**会话名**，且**两次冷启动后定位规则仍成立**。
- **失败判据**：只能取到窗口壳、取不到消息文本；或命名完全不稳定 → **R2 不成立**；若 R1 也不成立 → 触发 Q7。

**两次比对怎么做**：打开 `POC-02-结果-第1次.json` 与 `POC-02-结果-第2次.json`，对比这三个字段是否大体一致：
- `locatorRuleDesc`（定位规则描述字符串）
- `treeDepth`（UIA 树深度）
- `nodeCount`（节点数量级）

三者一致或相近 → 定位规则稳定；若 `messageAreaFound` 从 True 变 False 或定位规则明显不同 → 记为"命名不稳定"。

### 3.5 优雅降级与诊断（重要）
如果 `messageAreaFound=false`（只读到窗口壳），**脚本不会伪造任何消息文本**。它会输出诊断字段，请把这些原样回填：
- `controlTypeCounts`：各类控件的数量分布（看有没有出现 `Document`/`Text` 类节点）。
- `deepestSamples`：枚举到的最深层级节点采样（controlType / className / automationId / nameLen）。
- 可尝试的补救（都不改安装目录）：
  1. 在企微里**打开一个有历史消息的群并置前**，重跑；
  2. 以参数 `--force-renderer-accessibility` 重启企微后再跑（部分 Chromium 内容需要此开关才把网页内容暴露给 UI Automation）：
     `Start-Process "<企微主程序路径>" -ArgumentList "--force-renderer-accessibility"`
  3. 若企微窗口很小或消息区被折叠，先放大窗口。

### 3.6 Python 备用方案（仅在必须时）
```powershell
python -m pip install pywinauto          # 需安装，可能不被允许
python ".\POC-02-UIA读群消息.py" --run-index 1
python ".\POC-02-UIA读群消息.py" --run-index 2
```
- 没装 pywinauto 时脚本会**安全退出**并写出诊断文件（不会误判为 R2 失败）。
- **不确定点**：pywinauto 的 `element_info` 属性名与连接方式以官方文档为准；本脚本对属性访问均做了兜底，若个别属性名不同会退化为空值而不是崩溃。

### 3.7 回滚 / 中止
- 本 POC **全程只读**，不发送消息、不修改任何文件，随时按 `Ctrl+C` 中止即可。
- 「冷启动企微」就是**正常关闭再正常打开**，不存在需要额外回滚的状态。

## 4. POC-05：群机器人限频与超长行为实测（本批唯一的写动作）

> **纪律**：只在**专用内部测试群**执行；受控、单次、少量；全程留痕。
> 结论会用于标定令牌桶参数与内容校验（ADR V33/V35），**限频参数不得据猜测放宽**。

### 4.1 前置条件
1. **必须使用专用内部测试群**（用户已确认目前只有内部群可测）。
   > 补充事实（已核实，供参考）：企业微信帮助中心 `docid=14931` 与官方社区答复均表明「群机器人只支持内部群，外部群无法设置群机器人」。因此 **ADR 的 V24（外部群能否推送）在现有证据下倾向"不支持"**，但这仍需官方文档进一步确认，本批 POC-05 不负责验证 V24。
2. 需要一个**群机器人的 Webhook 地址**，获取步骤见 4.2。
3. webhook **只放在环境变量**里，绝不写进任何文件、绝不粘贴到聊天/文档。
4. 若手头有**两个不同的群机器人**（两个不同的测试群），可额外设置第二个变量用于 V35 计数维度验证；**只有一个也没关系**，脚本会输出 `INCONCLUSIVE_SINGLE_WEBHOOK`，不会瞎猜。

### 4.2 获取 WECOM_POC_WEBHOOK（群机器人 Webhook）步骤
依据企业微信帮助中心「如何设置消息推送」`docid=14931`：
1. 打开企业微信 PC 客户端，进入**专用内部测试群**。
2. 点群聊右上角 **`…`（三个点）** → **消息推送**（旧版叫「群机器人」）→ **添加**。
3. 选择 **新建**，给它起个可识别的名字（如 `POC测试`），创建完成后进入**消息推送详情页**。
4. 在详情页找到**Webhook 地址**（形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxxxxxx-xxxx-...`），点击复制。
   - 该 `key` 本身就是凭据（持有即可向该群发消息），**按密码级别对待**，泄露后应在详情页重新生成以作废旧 key。

在**目标机的 PowerShell 窗口**里设置（只对当前窗口生效，不落盘）：
```powershell
$env:WECOM_POC_WEBHOOK = "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=这里粘贴你的key"
# 可选：第二个机器人（不同测试群），用于 V35
$env:WECOM_POC_WEBHOOK_2 = "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=第二个key"
```
> 说明：`$env:` 设置的变量随窗口关闭即消失，不会写入系统环境变量，符合「凭据不落盘」要求。

### 4.3 第一步：自检（不发任何消息）
```powershell
cd D:\yizhan\hrm-dev\poc\wecom
python ".\POC-05-限频与超长.py"
```
**预期现象**：
```
==== POC-05 群机器人限频与超长实测 ====
[环境] Python 3.13.x | 间隔 3.0s | 计划发送 23 条（上限 30）
[目标] webhook1 = https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=****
[自检] 未发送消息（缺少 --confirm）。已写出自检结果：...\POC-05-结果.json
```
- 若提示 `环境变量 WECOM_POC_WEBHOOK 缺失`（退出码 2）：说明第 4.2 步没设置成功（注意变量要在**同一个 PowerShell 窗口**里设置并运行）。脚本**不会**回退到任何内置默认值。
- 输出里 `webhook1 = ...?key=****` 是**脱敏形式**，符合「脚本与结果不得出现完整 webhook」的要求。

### 4.4 第二步：真正执行（会往测试群发消息）
确认自检无误、且当前窗口指向**测试群**后：
```powershell
python ".\POC-05-限频与超长.py" --confirm
```
脚本会依次做四件事：
1. 发 1 条 `text`（基线）；
2. 发 1 条**超长 `markdown`**（构造约 4200 字节，> 4096 官方上限），预期返回 **40058**；
3. **限频探测**：以 **3 秒间隔发 21 条**（3 秒 × 21 条在任一 60 秒窗口内可越过 20 条上限）；
4. 若配置了第二个 webhook，再做 V35 交叉验证（向第二个机器人发 2 条）。

**预期现象（成功）**：
```
[1/4] 基线 text ...
  [HH:MM:SS.mmm] #1 baseline-text http=200 errcode=0 成功
[2/4] 超长 markdown（构造 4200 字节）...
  [...] #2 too-long-markdown http=200 errcode=40058 markdown 内容超长（实测返回 40058）
[3/4] 限频边界探测（21 条 × 3.0s）...
  ... 某条开始 errcode 非 0（限频表现）
==== 结论 ====
verdict = PASS
countDimensionVerdict = PER_ROBOT / INCONCLUSIVE_SINGLE_WEBHOOK
```

### 4.5 通过判据 / 失败判据（照抄 ADR 第 7 章）
- **通过判据**：得到可复现的**限频边界**与**超长错误码**，用于标定令牌桶参数与内容校验。
- **失败判据**：行为与预期不符 → 参数按实测重标；**限频参数不得据猜测放宽**。

### 4.6 硬性安全护栏（脚本已内建，不要试图绕过）
| 护栏 | 实现 |
|----|----|
| 总发送条数上限 | 硬编码 `MAX_TOTAL_SENDS = 30`，超限自动收敛 |
| 发送间隔下限 | 硬编码 `MIN_INTERVAL_SEC = 3.0`，传更小值会被强制提升 |
| 立即停止 | 在输出目录创建 `POC-05-STOP.flag` 文件，或按 `Ctrl+C`；脚本会优雅退出并写出**已采集的部分结果** |
| 必须显式确认 | 不带 `--confirm` 只做自检、不发消息 |
| webhook 保护 | 只从环境变量读取；输出只出现 `...?key=****`；不落任何文件 |

**中止示例**：
```powershell
# 另开一个窗口执行，脚本会在下一条发送前停下
```

### 4.8 回滚 / 中止
- 本 POC **无法撤回已发出的消息**（webhook 是单向推送）。因此：**只在测试群执行、条数受控（≤30 条）**。
- 若发现发错群：立即停止脚本、在群机器人详情页**重新生成 webhook**（作废旧 key），并删除/清理测试群中的测试消息。
- 停止后回收环境变量：关闭当前 PowerShell 窗口即可（`$env:` 变量随窗口消失）。

## 5. 六条判定标准自检对照表（ADR §14.2 W-C1 落地）

> ADR 要求「全部 6 条通过才认定落在 UI 层」。下表说明**本批 POC 套件**对这 6 条的自证情况。**注意：本批只做只读探测与受控发送，不等于整个三期方案已合规**；§14.2 的第 1/2 条需在**实现阶段**对采集端做装机自检。

| # | 判定项 | 本批 POC 套件的情况 | 可自查方式（在目标机运行） |
|---|----|----|----|
| 1 | 进程未被注入 | ✅ 本套件**不加载任何 DLL 到企微进程**，只枚举企微**已加载模块名**做文件名匹配（`Get-Process.Modules` / `tasklist /m`），属「查看」而非「注入」 | 对企微进程用 `tasklist /m /fi "imagename eq WXWork.exe"`，与本机官方安装基线比对 |
| 2 | 客户端文件未被修改 | ✅ POC-01 全程不写安装目录；`-Launch` 只传命令行参数，不改文件 | 运行前后对安装目录关键文件做哈希比对（命令见下） |
| 3 | 采集端不读进程内存 | ✅ 全套脚本**不含** `ReadProcessMemory` / `WriteProcessMemory` / 同类 API（用第 5.1 节命令可验证 0 命中） | 关键词扫描（见 5.1） |
| 4 | 不伪造协议 | ✅ POC-01/02 不构造任何指向企微服务端的请求；POC-05 只调用**官方 webhook 接口**（`qyapi.weixin.qq.com/cgi-bin/webhook/send`），不是"伪造客户端协议" | 抓包核对：不出现企微客户端未发起的请求 |
| 5 | 无 hook 类依赖 | ✅ 无 `frida` / `ntwork` / `wxwork_pc_api` 等；仅系统自带 .NET/PowerShell + Python 标准库 | 依赖清单 + 关键词扫描（见 5.1） |
| 6 | 无账号托管 | ✅ 本套件不保存、不读取任何账号密码；登录态由**人工在官方客户端完成**；POC-02 只是读取已登录窗口的可访问性树 | 检查脚本中无密码/token 字段；装机 checklist |

### 5.1 一键自证命令（在目标机 `D:\yizhan\hrm-dev\poc\wecom` 下执行）
```powershell
cd D:\yizhan\hrm-dev\poc\wecom

# ① 判定标准 3 / 5：确认无内存读取 API、无 hook 类依赖（期望：全部 0 命中）
Select-String -Path *.ps1,*.py -Pattern 'ReadProcessMemory','WriteProcessMemory','frida','ntwork','wxwork_pc_api','VirtualAllocEx','SetWindowsHookEx' |
  Measure-Object | Select-Object -ExpandProperty Count

# ② 判定标准 1：抽查企微进程已加载模块（与官方安装基线比对，不应出现第三方 DLL）
tasklist /m /fi "imagename eq WXWork.exe"

# ③ 判定标准 2：客户端文件未被修改（运行前后各跑一次，比对哈希是否一致）
Get-ChildItem "<企微安装目录>" -File | Get-FileHash -Algorithm SHA256 |
  Sort-Object Path | Format-Table -AutoSize
```

### 5.2 六条判定标准之外必须同时遵守的硬红线（本套件已内建）
- **脱敏**：结果文件会进 Git，脚本已做占位——会话名 `GROUP_n`、发送者 `MEMBER_n`、消息文本 ≤60 字符、手机号仅留后 4 位、邮箱/身份证占位；webhook 只以 `...?key=****` 出现。
- **不读内存**：脚本不含任何内存读取 API。
- **不改安装目录**：POC-01 不写安装目录、不写注册表。
- **重启需用户确认**：`-Launch` 有二次交互确认，且提供一键回滚。
- **未验证不得说验证**：见第 8 章。

## 7. 常见问题（FAQ）

| 现象 | 原因 | 处理 |
|----|----|----|
| 运行 `.ps1` 报「字符串缺少终止符」/ 中文乱码 | 脚本被以错误编码保存（丢了 BOM） | `git checkout -- hrm-dev/poc/wecom` 恢复；务必用 `powershell.exe`（5.1）运行 |
| 报「禁止运行脚本」 | 执行策略限制 | 用 `-ExecutionPolicy Bypass`（见 1.4） |
| POC-01 模块枚举为空 / 访问被拒 | 权限不足 | 以**管理员身份**打开 PowerShell 重跑 |
| POC-01 只读模式 verdict=INCONCLUSIVE | 正常（没带调试端口启动） | 按 2.3 用 `-Launch` 复测；不能据此判 R1 失败 |
| POC-02 `messageAreaFound=false` | 企微网页内容未暴露给 UIA，或没打开有消息的群 | 见 3.5 的三种补救 |
| POC-02 两次 `locatorRuleDesc` 不一致 | 定位规则不稳定（正是 V31 要验证的点） | 如实回填「命名不稳定」，不要修饰 |
| POC-05 提示变量缺失（退出码 2） | 环境变量没在**同一窗口**设置 | 在同一 PowerShell 窗口先 `$env:...=` 再运行 |
| POC-05 未触发限频 | 3 秒间隔护栏下刚好 20 条/分钟，未越界 | 属"合规未触发"，如实回填；**不得**为触发而缩短间隔 |
| 结果 JSON 里中文显示成 `\uXXXX` | PowerShell 5.1 的 `ConvertTo-Json` 会把中文转义 | 正常，仍是合法 JSON；用记事本/编辑器打开即可读 |
