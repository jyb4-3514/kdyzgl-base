### 1.2 分支流

`feature/* → dev → main`；**禁止直接提交 `main`**（D 档）；`dev → main` 合并与打 tag 属 C 档。

### 1.3 迭代阶段

一期 员工管理 → 二期 驿站包裹数据采集 → 三期 企业微信接入。

### 1.4 权限四档（一句话）

- **A 档 · 免确认**：读、本地改、本地构建/lint/test/verify、`hrm-demo` 内任意改、只读 MCP、非 `main` 分支 `git add`。
- **B 档 · 主智能体自决**：`git push`（非 main）、`feature → dev`、`deploy.sh`、重启服务/重载 Nginx、依赖安装/升级。
- **C 档 · 主智能体三步授权**：结构变更、数据回滚、删文件/清备份、证书/防火墙/宝塔配置、停服、`dev → main`、打 tag、凭据轮换与下发。须表单化输出：① 影响范围与是否涉生产数据 ② 是否可逆 ③ 回滚步骤与验证方法。
- **D 档 · 绝对禁止**：`push --force`/`reset --hard`/`clean -f`、直提 `main`、服务器改源码、凭据/业务数据入仓库·文档·日志·对话·演示工程、逆向签名/注入进程/绕过风控、无备份批量删改生产数据、公开生产 `*.map`、root 跑应用进程。**不接受任何授权。**

**审批纪律（不得无脑审批）：** 主智能体享有最高审批权限，但 C 档授权（§10.3）**必须以独立的安全技术评估结论为依据**：涉安全面的操作（鉴权 / 越权 / 外部暴露面 / 凭据 / 依赖 / 生产变更）先由网络安全工程师出结论，主智能体再决策与授权；**无评估结论不得授权**；安全工程师判定为高风险的，主智能体**不得直接放行**，须升级用户裁定。评估方（网络安全工程师）与决策方（主智能体）分离，不得由同一主体兼任。

**「安全评估」消歧（两类不得混用）：** ① **操作安全评估**（影响范围、是否涉生产数据、是否可逆、回滚步骤）——由**主智能体**按 §10.3 三步授权完成；② **技术安全评估**（漏洞、攻击面、鉴权与越权、依赖与供应链、合规红线技术判定）——由**网络安全工程师**出具结论。运维工程师**不承担上述任一类评估**，其职责是按主智能体授权执行变更。

## 4. 组合命中优先级

同一任务命中多个角色时，按下表**自上而下**判定先行者（先命中先执行）：

| 优先级 | 规则 | 判据（一句话） | 依据 |
| --- | --- | --- | --- |
| P0 | 权限先行 | 任何任务先过 §10 分档；C 档先授权，D 档直接拒绝（不接受授权） | §10.1–§10.4 |
| **P0.5** | **安全评估先行** | 安全面涉及 **鉴权 / 越权 / 外部暴露面 / 凭据 / 依赖 / 生产变更** 时，网络安全工程师**先出结论**，主智能体**后授权**；不得由主智能体跳过评估直接放行 | §7.2 §10.3 |
| **P0.6** | **技术评审先行（方案闸门，新增）** | 凡产出**方案阶段产物**（ADR / 四件套 / 接口契约 / 数据库设计 / 部署方案 / 需求口径方案），**必须经技术评审工程师评估通过（通过 / 有条件通过）后才能报主智能体审批**；「打回」不得报审 | §8（第 8 条）§9.2 |
| P1 | 口径先行 | 命中计费/提成/SLA/考核口径 → 先经用户确认，再算法，再实现 | §11.4 |
| P2 | 设计先行 | 命中界面视觉/交互 → UI/UX 先，前端后 | §8.1 |
| P3 | 模型先行 | 命中 §11.1 场景 → 算法先出「四件套」，后端后实现 | §8.2 §11.3 |
| P4 | 结构先行 | 命中表结构变更 → 数据库先出 DDL/迁移，后端再改 Mapper；大表变更须数据库+算法联评 | §6 §6.8 |
| P5 | 契约先行 | 命中跨层接口 → 先定 `api.md` 契约，前端/测试后开工 | §1.3 |
| P6 | 守卫收口 | 任何合流点（提交前/合并前/上线前）→ 主智能体 `code-review` 把关，未过不得视为完成 | §8 §9.1 |

**插入说明：** P0.5（安全评估先行）、P0.6（技术评审先行）为新增，插入 P0 与 P1 之间；P1–P6 的序号与语义**保持不变**，仅在其上方增加两条先行规则。P0.5 与 P0.6 **并行不互替**：前者管安全面、后者管工程面，二者可同时前置，但都不替代主智能体的操作安全评估与授权。

## 5. 标准链路（串行）

| 链路 | 阶段 → 责任人 | 门禁 | 打回条件 |
| --- | --- | --- | --- |
| **L1 需求→架构→Review** | 需求（主智能体）→ 架构设计/ADR（架构师）→ Review（主智能体 `code-review`） | 架构文档含模块边界 + 接口/数据顶层设计 + ADR；NFR 清单齐 | 无 ADR、无取舍理由、与 `api.md`/`db.md` 冲突、出现无源结论 |
| **L2 设计→前端→测试（§8.1）** | 设计方向/Tokens/组件规范（UI/UX）→ 前端按 Tokens 实现 → 功能/接口/E2E/门禁实跑与响应式·可访问性验收（测试工程师）；**视觉走查报告由 UI/UX 出** | 设计规范冻结（Tokens 明确）；前端 build/lint 通过；测试覆盖四态（loading/empty/error/normal） | 前端跳过设计自定视觉、Tokens 未冻结即实现多页、对比度 < 4.5:1 |
| **L3 算法→后端→测试（§8.2）** | 算法方案「四件套」（算法工程师）→ 后端落地实现（后端工程师）→ 测试按基准数据回归（测试工程师） | 四件套齐全；参数外置可配；失败降级存在；基准 before/after 可复现 | 算法方案未定即开工后端、阈值/权重硬编码、无基准对比 |
| **L4 建表→后端→部署（§6 单 MySQL + Flyway）** | DDL/迁移脚本（数据库工程师）→ 后端改 Mapper/接口（后端工程师）→ 部署（运维工程师，主智能体 C 档授权） | 迁移脚本新版本号（不改历史）；快照与迁移同步；上线前备份 | 改历史脚本、只改快照不写迁移、大表变更未联评（§6.8） |
| **L5 缺陷修复→测试复现** | 复现与根因（测试工程师）→ 修复（对应实现角色）→ 回归验证（测试工程师）→ 合流（主智能体） | 有最小复现步骤与复现用例；回归通过；门禁基线不弱化 | 无复现步骤即改代码、为通过改验收资产、门禁劣化未归因 |
| **L6 架构→运维（部署类方案）** | 部署/回滚方案（架构师）→ 部署手册（运维工程师）→ 执行（运维，主智能体授权） | 手册含回滚路径；Nginx 四关键项保留；单一托管方式（`RESTART_MODE=bt`） | 缺少回滚步骤、双托管抢 8080、未备份即变更 |
| **L7 安全评估 → 授权 → 实现** | 威胁建模与静态审计（网络安全工程师）→ 技术结论与风险分级 → 主智能体 C 档授权（**不得无脑审批**）→ 实现角色修复 → 安全复验（网络安全工程师）→ 合流（主智能体） | 评估报告含威胁建模 + 发现项（严重级/可利用性/影响面）+ 复现步骤 + 修复建议；授权三步表单齐全；复验结论明确 | 无评估结论即授权、凭经验放行高风险项、由评估方兼任授权方 |

## 6. 并行与免派发判据

### 6.1 允许 fan-out 并行的三条判据（须同时满足）

1. **无产物依赖**：任一子任务的输入不含另一子任务的输出（对照 `agent-team-design.md` §5 台账的生产者/消费者关系）。
2. **不共享可写文件**：各子任务写入路径互不重叠（规避 SESSION-STATE「并发冲突记录」教训）。
3. **不含需先授权的 C 档动作**：C 档动作串行且须主智能体授权（§10.3）。

### 6.2 不可并行反例（必须串行）

| 反例 | 原因 |
| --- | --- |
| 算法方案未定即并行开工后端实现 | 违反 §8.2 硬性要求、P3 模型先行 |
| 表结构未定即并行写 Mapper / 迁移脚本 | 违反 P4 结构先行 |
| 设计 Tokens 未冻结即并行实现多页面 | 违反 §8.1、P2 设计先行 |
| 两会话并行改同一工作区同一分支 | SESSION-STATE 并发冲突先例；须停手回报主智能体 |
| **安全评估未出结论即并行执行 C 档生产变更** | 违反 P0.5 安全评估先行、L7 与跨切面规则 |
| **方案未过技术评审即并行报审 / 并行开工下游实现** | 违反 P0.6 技术评审先行、L8 与 §8 第 8 条硬性闸门 |

### 6.3 无需派发的判据（委派开销 > 收益）

**判据（须同时满足）：** ① 步数 ≤ 5；② 完全落在单一角色技能范围内（单文件小改/只读检索/条款核对/文档同步/分支与提交范围核对/上下文压缩）；③ 未命中 §11.1 算法触发、§8.1 UI/UX 强制派发、路由表任一路由信号；④ 需写入的工程目录数 ≤ 1。

**免派发清单：**

| # | 事项 | 依据 |
| --- | --- | --- |
| 1 | 只读检索、查询、条款核对、差异比对 | §10.1 A 档 |
| 2 | 文档同步（`update-log.md` 行、`SESSION-STATE.md` 检查点写入） | §13 |
| 3 | 分支/文件范围核对、提交前自检 | §2 纪律 2、§13 |
| 4 | 上下文压缩与交接摘要 | §8 权限与流程 |
| 5 | 单文件 ≤ 约 20 行的文案/间距/样式微调（不涉 Vue 工程结构） | §8.1 |
| 6 | 用户明确指定由主智能体直接产出的一次性文档 | 用户指令 |

**必须派发边界：** 需写 ≥ 2 个工程目录，或命中 §11.1 / §8.1 / 路由表任一信号 → 强制派发对应角色。

## 12. 检查点、记忆与并发纪律

> 本节针对两类反复出现的问题——「**换对话就失忆**」与「**多会话互相覆盖**」——把纪律写成可判定条目。
> 背景：TRAE 记忆按**工作区路径**分桶（`~/.trae-cn/memory/projects/<路径特征>/`），且记忆内容偏"约束与偏好"，**不含进行中的任务进度**；进度必须靠本文件与 `SESSION-STATE.md` 承载。

| # | 条目 | 判定标准 | 违规后果 |
| --- | --- | --- | --- |
| M01 | **入口优先** | 新会话先读 `AGENTS.md` + `SESSION-STATE.md` 顶部摘要，再动手 | 凭对话记忆开工 → 重复劳动、踩已踩过的坑 |
